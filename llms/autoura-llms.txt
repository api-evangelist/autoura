# Autoura

> Autoura is a UK digital experience platform (DXP) for real-world tourism. It structures and
> maintains experience data — venues, attractions, tours, routes, stops, accessibility and
> hospitality signals, AI guides and storytelling — so that AI systems can understand and act on it.
> Autoura's primary integration surface for agents is a hosted MCP server; its REST API serves
> routes, stops, visits, characters, MoveMe audio and a consent-brokered consumer preference graph.
> PlanMyVisit is Autoura's consumer visit-planning product on the same MCP endpoint.

## Agent surfaces (provider-published)

- [Autoura agent skill](https://www.autoura.com/core/pai/skill.md): the B2B operating guide — what
  Autoura is, when to hand off to PlanMyVisit, authentication, the strategy/execution document split,
  the PAI identity model, tasks, and entity definitions with ID prefixes.
- [PlanMyVisit agent guide](https://www.planmyvisit.to/skill.md): the consumer operating guide —

  venue, create/refine/resume.
- [PlanMyVisit tool reference](https://www.planmyvisit.to/docs/ai/tools.md): the provider's selected
  MCP tool descriptions. Autoura instructs agents NOT to hard-code tool names and to call tools/list
  at the start of every session.
- [PlanMyVisit llms.txt](https://www.planmyvisit.to/llms.txt): the consumer brand's own llms.txt.
- [MCP endpoint](https://api.autoura.com/api/mcp): hosted remote MCP server. OAuth 2.1 + PKCE +
  dynamic client registration, or a documented email-code bearer token. Anonymous tools/list returns
  401 with an RFC 9728 challenge.
- [WebMCP](https://www.planmyvisit.to/webmcp): the same tool set exposed in-page on PlanMyVisit,
  authenticated by the website session.

  religious and medical diets keyed on IATA airline special-meal codes.

  addressed by DID, with DIDComm v2 messaging.

## Notes for agents

- There is no OpenAPI, no GraphQL, no AsyncAPI and no A2A agent card. The machine-readable contract
  is the MCP tool set, and it is auth-gated.
- There is no idempotency key and no dry-run mode. Retrying a create after a dropped response will
  create a second object. Autoura's guidance is behavioural: check for an existing object first.
- There is no published rate limit and no rate-limit header, so there is no runtime budget signal.
- The API is unversioned and the changelog records field removals and renames. Read it before you
  depend on a field.
- Autoura tells agents never to fabricate venue facts and to file a content_gap_report instead.
