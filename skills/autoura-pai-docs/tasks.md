## What this is about

This document explains:

- what tasks are for
- when to create a new task
- when to update an existing task instead
- how to use notes, status, and workflow clearly
- how brands should hand work back to Autoura

This is **execution**, not strategy.

---

## What this object is

A **task** is a unit of tracked work used for project management, support, coordination, and live operational orchestration.

Tasks are used to:

- track work over time
- coordinate between users
- record progress
- support handoff
- make operational work visible and structured

Tasks are for work happening in or through Autoura.

They are not intended as a general private task manager for unrelated off-platform work.

---

## When to create vs reuse

Create a new task when:

- the work is genuinely new
- the work should be tracked separately
- the issue, request, or action has its own lifecycle

Reuse an existing task when:

- the work is already being tracked
- new information belongs to an existing issue
- the task is still active and relevant

Important:

- always search for an existing relevant open task before creating a new one
- do not create duplicate parallel tasks for the same work
- if a relevant task exists, update it instead

---

## What tasks are for

Tasks serve four main purposes:

### 1. Project management

Examples:

- onboarding
- setup
- configuration
- launch preparation
- follow-up work

### 2. Workflow management

Examples:

- work that moves through multiple steps
- work with ownership changes
- work that depends on status changes over time

### 3. Visit or route orchestration

Examples:

- operational exceptions
- follow-up actions
- live coordination needs
- intervention during an experience

Tasks are not intended as fine-grained live navigation state.

### 4. Support questions

Examples:

- investigating a problem
- tracking a brand request
- coordinating a support response
- following up on an issue

---

## Shared task model

Tasks are shared across the platform by operational users, including for example:

- Autoura users
- brand users
- suppliers
- affiliates
- designers

Consumers / profiles do not share tasks directly.

However, consumer actions, requests, and issues may create tasks.

## Typical workflow

1. Search for an existing relevant open task
2. If one exists, update it
3. If not, create a new task
4. Add notes as work progresses
5. Keep status and next action clear
6. Hand work back appropriately when your part is done

---

## Notes

Use notes to keep a readable timeline of execution.

Add a note when:

- something was done
- something was learned
- the situation changed
- new information arrived
- work was handed on

Notes should help another person or agent understand what happened without relying on memory.

---

## Status and handoff

Keep task status current and meaningful.

Use status to reflect:

- whether work is new
- in progress
- blocked
- awaiting someone else
- complete
- handed back for orchestration

### Brand-side completion rule

Brand users should **not** mark tasks complete.

When a brand has done its part:

1. add a note explaining what was done or what is now true
2. set the task status to **`awaiting_orchestration`**
3. let Autoura decide the next step, follow-up, or closure

This keeps workflow clear and avoids premature closure.

---

## When tasks are especially useful

Tasks are especially useful when work needs to be:

- coordinated across time
- reviewed later
- picked up by another user
- tracked through multiple steps
- kept visible beyond a single conversation

---

## Example: support question

A guest, brand, or partner raises an issue that requires work rather than a one-line answer.

Recommended approach:

1. search for an existing relevant open task
2. if one exists, update it with a note
3. if not, create a new task
4. record progress through notes and status updates
5. when the brand has done its part, set the task to `awaiting_orchestration`

---

## Example: task coordination

A task already exists and now needs work.

Recommended approach:

1. open the task and review its context
2. understand the objective and required outcome
3. do the work
4. add a note explaining what was done or learned
5. update the status or workflow state clearly
6. if the brand has finished its part, set `awaiting_orchestration`

---

## Example: live orchestration

An issue arises during a visit or route that should not be lost.

Recommended approach:

1. search for an existing relevant task
2. update it if one exists
3. otherwise create a new task
4. record actions and progress
5. keep the next action clear
6. hand back to Autoura when appropriate

---

## Checklist

- Existing relevant open task checked first
- No duplicate task created
- Clear objective or reason for task
- Notes added as work progresses
- Status kept current
- Brand handoff uses `awaiting_orchestration`

---

## Common pitfalls

- creating duplicate tasks
- treating tasks as private notes
- failing to add notes as work progresses
- leaving status unclear
- marking tasks complete from the brand side
- using tasks for unrelated off-platform personal work
